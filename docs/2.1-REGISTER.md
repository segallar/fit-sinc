## Цель

Позволить новому пользователю создать аккаунт **без админки и CLI**, войти в кабинет и дальше подключить Hammerhead / Garmin в **Settings**.

**Не цель 2.1:** подтверждение email, invite-only, captcha, OAuth — см. фазы ниже.

| Config | `REGISTRATION_OPEN` в [`.env.example`](../.env.example) |

### Поведение

- `REGISTRATION_OPEN=false` → `GET /register` → страница «регистрация закрыта» (403).
- `REGISTRATION_OPEN=true` → форма; дубликат email → ошибка; слабый пароль / mismatch → ошибка.
- Уже залогинен → `303 /app/`.
- Новый user: `is_admin=0`, каталог `data/users/{slug}/` создаётся при первом sync/OAuth.

### Онбординг после регистрации (ручной, без 2.6)

1. `/app/` — дашборд, баннер подключений (**1.8**).
2. **Settings** → Hammerhead OAuth (`hammerhead_user_id` для webhook).
3. Garmin — **первый** login пока через CLI или import cookies (**1.2**); refresh/status в UI.

## Email — отдельная подфаза **2.1e** (не сделано)

### Проблема

Без проверки email любой может зарегистрировать чужой адрес → письма/уведомления (будущие), восстановление пароля, доверие к аккаунту.

### Целевое поведение

```text
POST /register
  → users.email_verified = 0, status = pending
  → письмо со ссылкой /verify-email?token=…
  → до клика: вход запрещён ИЛИ вход есть, но sync/HH disabled (выбрать при проектировании)
POST /verify-email
  → token одноразовый, TTL 24–72 ч
  → email_verified = 1, status = active
```

### Варианты политики до подтверждения

| Вариант | Плюсы | Минусы |
|---------|--------|--------|
| **A. Нет входа до verify** | проще безопасность | хуже UX после register |
| **B. Вход есть, sync выкл.** | как сейчас auto-login + баннер «подтвердите почту» | нужен guard в sync/webhook |
| **C. Grace period 24 ч** | компромисс | сложнее |

**Рекомендация для GetSync:** **B** — после register auto-login на `/app/` с flash «Проверьте почту»; webhook/sync для user с `email_verified=0` не выполнять.

### Задачи 2.1e (оценка 1–2 вечера + SMTP)

| ID | Задача |
|----|--------|
| 2.1e.1 | Миграция SQLite: `email_verified`, `email_verify_token`, `email_verify_sent_at` |
| 2.1e.2 | `POST /register` → pending + send mail (SMTP env / SendGrid) |
| 2.1e.3 | `GET /verify-email?token=` → activate |
| 2.1e.4 | Resend + rate limit на send |
| 2.1e.5 | Guard sync + banner в кабинете |
| 2.1e.6 | Тесты (token expiry, duplicate verify) |

### Env (черновик)

```env
SMTP_HOST=
SMTP_PORT=587
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=noreply@getsync.me
APP_PUBLIC_URL=https://app.getsync.me
```

### Связь с roadmap

- Полный пакет (invite, captcha, политика пароля) остаётся в **2.6** ([PLAN.md](PLAN.md)).
- **2.1e** — минимальный верификационный контур, можно выпустить раньше 2.6.
